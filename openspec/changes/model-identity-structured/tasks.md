## 2. 目錄與序列化

- [x] 2.1 `ModelRow`（於 `Sources/BestASRKit/Store/StoreTables.swift`）改為持有 `ModelID` 與 `Quantization`，取代四個鬆散字串欄位；`ModelRow.id(...)` 保留為相容入口，內部由 `ModelID` 組出四段字串。**行為**：序列化形式維持 `runtime|family|size|quantization`；`ModelRow` 的 JSON 欄位維持平坦（`family` / `size` / `quantization` 三個頂層字串鍵），不因型別改變而變成巢狀。**驗證**：新增測試檔 `Tests/BestASRKitTests/ModelRowCodecTests.swift`（本任務建立；Swift Testing），讀入**已提交的** `docs/model-identity-audit.csv`（37 筆，內容為 `~/.bestasr/store/models.jsonl` 的快照）的 `model_id` 字串、重新序列化，主張與輸入**逐字相同**。以已提交檔為準而非家目錄檔，是因為後者在 CI 不存在時測試會靜默空過；測試須主張檔案存在、列數非零，且其中**至少各有一列** size 與 quantization 為 `default`，以確保最難的兩類確實被走到。`~/.bestasr/store/models.jsonl` 存在時另做一次相同主張作為交叉檢查，不存在則跳過該則而不影響前者。（實作 design D2：對機序列化沿用四段字串，由 `ModelID` 產出。滿足 benchmark-store 的 "The persisted model key is unchanged by the identity refactor"）
- [x] 2.2 移除 `ModelGrid.row(backend:modelAddress:)` 的雙文法與裸 size fallback，改為以 `ModelID` + runtime 查找。**行為**：任一查找至多命中**一個模型**；不再有「first row wins」的靜默歧義。（同一模型底下仍可有多列——那是量化變體，依偏好排序，如 `whisper.cpp tiny` 的 `q5_1` 與 `q8_0`；被消除的是**跨模型**的歧義。）使用者輸入的字串另由 `ModelGrid.identity(backend:matching:)` 解析：命中零個或多於一個模型時回 nil，由呼叫端據此拒絕，而非代為挑一個。**驗證**：`ModelGridTests` 新增測試，主張 `ModelID("canary","1b")` 與 `ModelID("mms","1b")` 各自命中自己的列且互不返回對方；並主張裸字串 `"1b"` 解析為 nil（歧義），而 `whisper.cpp` 的 `"tiny"` 仍解析成功（無歧義的裸 size 不受影響）。（滿足 model-grid 的 "Model identity is a structured value, not a formatted string"）
- [x] 2.3 正規化 grid 列的 `size`，使其等於 pinned upstream artifact 宣告的版本。已知待改：`mlx-audio` 的 parakeet 列 size 由 `0.6b` 改為 `0.6b-v3`（pin 為 `mlx-community/parakeet-tdt-0.6b-v3`）。**行為**：同一模型在不同 runtime 下取得相同 `ModelID`。**驗證**：`ModelGridTests` 新增一則測試，主張 fluid-parakeet 與 mlx-audio 兩列的 `ModelID` **相等**。（實作 design D3：`size` 正規化是前提，不是附帶清理。滿足 model-grid 的 "Size is normalised to the pinned upstream artifact"）
- [x] 2.4 將 grid 每一列的 quantization 由字串改為 `Quantization` 值，依 `docs/model-identity-audit.csv` 的分類逐列指派，**19 列全部涵蓋**：`apple-speech` 1 列 → `notApplicable`；`fluid-*` 3 列 → `named`（值由任務 5.1 決定：parakeet `int8`、paraformer `fp16`、sensevoice `fp16`）；whisperkit 6 列 → `deferred(.runtime)`；canary → `named("q8")`，取自其 pin `Mediform/canary-1b-v2-mlx-q8`；**其餘 8 列 mlx-audio reference row → `unknown`**——原任務只點名其中 2 列（`mega-asr`、`qwen3-forcedaligner`），漏掉 6 列：4 列 pin 了 repo 但該 repo 未宣告精度（`moonshine/base`、`nemotron-asr/streaming`、`parakeet/0.6b-v3`、`whisper/large-v3-turbo`），2 列連 repo 都沒有（`distil-whisper/large-v3`、`mms/1b`）。這 8 列全屬未 bundle 的 reference catalog，不會進入 benchmark 候選。**行為**：`Sources/` 中不再有任何列以 `default` 作為 quantization 或 size 的值；唯一允許出現該字面值的位置是 `ModelID.removedPlaceholder` 常數本身（見 design 的 Acceptance criteria，該例外為封閉列舉）。**驗證**：`ModelGridTests` 新增三則測試——(a) 沒有任何列的 quantization 是 `.named("default")`；(b) `unknown` 的列**恰好**是上述 8 列（封閉列舉，**不得依性質相似擴充**，新列要成為 `unknown` 必須刻意改這則測試）；(c) apple-speech 為 `notApplicable`、whisperkit 6 列為 `deferred(.runtime)`、fluid 3 列為 `named` 且值分別為 int8 / fp16 / fp16。
  - **未closed的項目（size 軸）**：`mega-asr` 與 `qwen3-forcedaligner` 兩列的 **`size` 仍是 `default`**。spec model-grid 規定該字面值不得作為 size 出現，但上游兩者都沒有公布版本名，而 `ModelID` 要求 size 非空。三個可能解各有代價：(i) 移除這兩列——會讓 `mlxFamilies` 從 15 掉到 13，破壞既有的 reference catalog 主張；(ii) 另編一個 size 字串——那只是換名字的佔位字；(iii) 放寬 spec，容許「family-only」的 reference row。**未擅自選擇**；ModelGridTests 的封閉列舉已具名這兩列，缺口可見而非隱形。（滿足 model-grid 的 "Quantization is a closed enumeration with no placeholder"）

- [x] 4.1 [P] `StoreProjection` 移除針對 `mlx-audio` 的三元運算子，改為直接以四段建構 `ModelID`，並於投影結果標示身分是否完整（`BenchmarkRecord` 新增 `identity` 與 `identityComplete`）。**位址是否帶 family 改由「裸 size 在該 runtime 下是否有歧義」決定**，不再依 backend 名稱分支。**`parts[1] == parts[2]` 的 legacy 修補保留**——原任務要求一併移除，但實查 store 發現**仍有 4 個這種 id**（`whisperkit|base|base|default`、`whisperkit|tiny|tiny|default`、`whisper.cpp|base|base|q8_0`、`whisper.cpp|tiny|tiny|q8_0`），移除會讓它們的 family 變成 `base`／`tiny`，與同一候選的新量測靜默分家。該修補的退場屬於歷史記錄重新編碼那個 change；此處僅去掉它對 backend 的條件（目錄中沒有任何 family 等於自己的 size）。**行為**：投影後 family 不再被丟棄；不完整的記錄被標記而非靜默。**驗證**：新增一則測試，主張一筆非 mlx 的 `model_id` 投影後其 `ModelID.family` 等於字串中的第二段（今日為丟棄後補回的 `whisper`），並主張一筆 `unknown` quantization 的記錄被標為不完整。（滿足 benchmark-store 的 "Records carry whether their identity is complete"）

## 8. 本 change 未關閉的項目（明列，不得當作已覆蓋）

- [ ] 8.1 **`CommandCore` 的 seeding fallback 會捏造 family**。`Sources/BestASRKit/CommandCore.swift` 在 `ModelGrid.identity(backend:matching:)` 回 nil 時，以 `family: "whisper"` 組出 `modelId` 並**寫進 store**——不論該記錄來自哪個 runtime。任務 2.2 讓 nil 多了「歧義」這個新來源，因此**擴大了這條捏造路徑的可達範圍**。正解不明顯（位址若是裸 size 且解析不出來，我們是真的不知道 family；三個選項——以位址字串內的 family 為準、拒絕寫入並具名警告、寫入 sentinel——各有代價），故**不在本 change 內擅自決定**。註：`Sources/BestASRKit/Store/BenchmarkStore.swift` 同樣寫 `family: "whisper"`，但那是 legacy flat-cache 遷移路徑且註解明載「legacy era was whisper-only」，屬已知事實而非捏造，**不在此項內**。
- [ ] 8.2 **legacy `default` 量測是否該退出 measured ranking —— 與 C1 是同一個矛盾**。
  - **規模更正**：先前寫「35 筆」是錯的，實測為 **344 / 383（89%）**。那個錯誤數字正是本項被判為「可延後」的全部依據；DA 與 regression lens 各自獨立指出這點。
  - **現況**：`Quantization.isComplete` 修正後這 344 筆被標為不完整，但 `Router` **完全不讀** `identityComplete`（全 repo 只有 `CommandCore.listModelsJSON()` 與測試讀它）。
  - **兩份 spec 都寫了 SHALL**：`benchmark-store` 的「records marked incomplete are excluded from the ranking, and their exclusion is stated rather than silent」與 `asr-routing` 的「The router SHALL exclude any candidate whose identity is incomplete」。
  - **為什麼不逕行實作**：照做會讓 89% 的量測退出排序，本機幾乎每一個 measured recommendation 都退回 cold-start prior。這不是規則錯，是**規則與未遷移的 store 不相容**——與 C1 是同一件事的兩個面。三條出路（見 master report）沒有選定之前，實作它等於單方面選了其中一條。
  - 任務 3.3 與 7.1 已退回 `[ ]`，不再宣稱完成。
- [ ] 8.3 **`mega-asr` 與 `qwen3-forcedaligner` 的 `size` 仍是 `default`**（詳見任務 2.4 的說明）。
